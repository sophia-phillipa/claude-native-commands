# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Run from the repository root. `S` is `.claude/skills/notebooklm-command-infographic-playbook/scripts`. `<slug>` is a card id such as `compact` (no `/`).

- All tests: `cd S && python3 -m pytest -q -p no:cacheprovider tests`. Add `--basetemp=<dir>` to keep pytest's temp directories out of `/tmp`.
- One test: `cd S && python3 -m pytest -q -p no:cacheprovider "tests/test_blueprint_rules.py::test_fixture_set_is_the_agreed_one"`. To select by name, use `-k <expr>` instead.
- Lint: `cd S && ruff check .`
- Tool help: `python3 S/infographic-register-tool.py --help` lists the subcommands. Without `--root`, the script searches upward from the working directory for the project root.
- Register pipeline, in order:
  - `check-blueprint <slug>`: barrier 1, before the NotebookLM run.
  - `labels <slug>`: prints the lines for `roteiro.md`.
  - `snapshot-downloads --out <file>`: before each download.
  - `collect-download <slug> --snapshot <file> --kind png`: moves the new PNG into the asset folder.
  - `check-qa <slug>`: barrier 3, after `qa-report.json` is written.
  - `register <slug>`: needs `check-blueprint` and `check-qa` to pass; writes the outputs.
- Vector fallback, only when Sophia asks: `render-template`, `check-vector`, `render-fallback`.

## Architecture

- `src/comandos-nativos.html` is the only page file edited by hand. It is a fragment (it starts at `<title>`, with no doctype) that holds one inline script.
- `comandos-nativos.html` at the root is generated. It is 254 bytes of head, then the source bytes, then the 9-byte tail `\n</html>\n`. Never edit it; `register` rebuilds it.
- Card data lives in JS arrays inside that script: `COMMANDS`, `NEW_COMMANDS`, `LOTE7_COMMANDS`, `LOTE8_COMMANDS` and `LOTE9_COMMANDS`, plus `ICONS`, `CONTEXTS`, `CATEGORIES`, `MOTION` and `DOCS`. The lote arrays are pushed into `COMMANDS` at load.
- `NOT_IN_APP` filters only `NEW_COMMANDS` and its category and motion maps. `LOTE7_COMMANDS`, `LOTE8_COMMANDS` and `LOTE9_COMMANDS` are pushed without that filter; they contain no `NOT_IN_APP` ids today.
- The block between `INFOGRAPHICS:BEGIN` and `INFOGRAPHICS:END` is generated by `register` (format paths and `model_mode` per slug). Do not edit it by hand.
- Per-command files live in `assets/infographics/<slug>/` (`blueprint.json`, `nota.md`, `roteiro.md`, `qa-report.json`, the audited `infographic.png`, `infographic.webp`, `infographic-1920.png`). `assets/infographics/manifest.json` indexes them, with the top-level keys `items` and `version`.
- The image is made by NotebookLM Studio in Chrome, not by a script. The script checks the blueprint and the audit, collects the download and registers the result, which writes the manifest item, the INFOGRAPHICS block and the standalone page together.
- The audited `infographic.png` is gitignored and stays local; only the WebP and the 1920 px PNG ship.
- Contracts: `work/infographic-contracts.md`. Its section 8 and the page's INFOGRAPHICS comment still name `register_and_check.py`; the real script is `infographic-register-tool.py`.
- Tests in `S/tests/`: blueprint rules, the template layout (Playwright) and the register and check pipeline.
- `S` is gitignored: the script and its tests stay local while the posters are generated. The repos ship the page, its poster images and at most the NotebookLM skill.
- `dossier/` (local only, gitignored, like everything in `work/` except `work/infographic-contracts.md`) holds long-task state: `*-progress-reference.md` notes and `*-tasks-reference.json` lists whose `status` is `pass`, `pending` or `fail`.
- Publishing: only the main session publishes the page, as a private claude.ai artifact built from `src/`, with the asset files and downloads capability. No script publishes.
- Checks before each publish (manual, no script yet):
  - `node --check` on the page's main inline script, extracted to a temp file;
  - the page served on localhost, with 0 console errors at 375 and 1280 px and no horizontal scroll;
  - every rendered card has 3 examples and an entry in `CATEGORIES`, `CONTEXTS`, `ICONS` and `MOTION`.
- Language: card text and README.md are pt-BR (no English README, Sophia's choice); code, identifiers, comments and the other docs are English.
- README covers only the page: no install, how-it-works, prerequisites, uninstall, configuration, known-issues, tests, development, changelog, contributions, maintainer or license section, and no `SECURITY.md` (Sophia, 2026-11-23). This overrides the mandatory sections of `github-readme-playbook`.
